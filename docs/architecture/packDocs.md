# Documentation and build-artefact tools (`packDocs`, `buildInfo`)

Merged from the experimental CMSIS Pack Docs extension. Two pure cores, two
handlers, one dispatch seam, wired into the MCP server and the multi-window
router the same way as the serial tool group.

## Layout

| Path | What | Imports `vscode`? |
| ---- | ---- | ----------------- |
| `src/core/packDocs/` | Target resolution from `*.cbuild-run.yml` (`cbuildRun.ts`, `targetDocs.ts`), pdsc `<book>` walking (`pdscBooks.ts`), Arm document catalogue and download (`armDocs.ts`, `webFetch.ts`), user and workspace document folders, `pdftotext` extraction (`pdfExtract.ts`), the on-disk page store and BM25 index (`pageStore.ts`, `bm25Index.ts`, `search.ts`), peripheral dossiers over the SVD (`svdLite.ts`, `coreSvd.ts`, `peripheralDocs.ts`), renderers | no — everything arrives through `PackDocsHost` (`host.ts`) |
| `src/core/buildInfo/` | ELF32 reader (`elf.ts`, positioned reads, no library), GNU ld / armlink map parser (`mapFile.ts`), build-log diagnostics (`buildLog.ts`), artefact discovery from cbuild-run / cbuild files (`artifacts.ts`), region usage (`usage.ts`), renderers | no — `BuildInfoHost` |
| `src/packDocsHandler.ts`, `src/buildInfoHandler.ts` | One `handle*` method per tool, a timeout fence per call (`timeoutMs` up to 600 s — indexing a 3 000-page manual takes minutes), traces in the output channel, panel-only inspection methods | no |
| `src/packDocsTools.ts`, `src/buildInfoTools.ts` | The MCP tool names and zod schemas; call the dispatch, never a handler | no |
| `src/packDocsDispatch.ts` | `PackDocsHandlers { docs, build }`, `PackDocsDispatch`, `localPackDocsDispatch` | no |
| `src/packDocsHost.ts` | Settings (`cmsis-developer-assistant.packDocs.*`, `.buildInfo.*`), the host objects (pack root, `globalStorage/packdocs`, `assets/`, `findFiles`), `createPackDocsHandlers` | yes |
| `src/packDocsCommands.ts` | Palette commands: list / index target documentation, import a document for the current target (attribution wizard), open the user documents folder, open the panel | yes |
| `src/packDocsPanel.ts` | The Pack Docs webview panel: target and documents, SVD peripherals, page store, in-process tool runner | yes |
| `assets/svd/core/` | 16 Cortex-M core-peripheral SVDs + `index.json`, generated by `scripts/core-svd/` (not shipped) | — |

## Wiring

- **Op table** (`src/core/opTable.ts`): `PACKDOCS_DOC_OPS` (5) and `PACKDOCS_BUILD_OPS` (5) form `PACKDOCS_OPS`; `isPackDocsOp` / `isPackDocsDocOp` pick the handler; the five documentation ops are `SLOW_OPS` (10-minute router floor). Compile-time coverage against the `handle*` methods of both handler classes.
- **Every window** builds the handler pair at activation (`extension.ts` → `createPackDocsHandlers`) — they do nothing until called — and hands it to its `ControlServer`, so a forwarded op executes in the window that owns the workspace: `dispatch(op)` is three-way (serial → serial singleton, pack-docs → `docs` or `build`, else the debugging handler).
- **Router**: `RoutingDebuggingHandler.packDocsOp` forwards like `serialOp`; `WindowCoordinator.sessionHandlers()` returns `packDocs: (op, args) => router.packDocsOp(op, args)`. The tools carry no path, so they resolve through the pinned / cached / sole-window rungs, exactly like `cmsis_action`.
- **Gates**: `DebugMCPServerOptions.packDocsEnabled` and `buildInfoEnabled` (default `false`), fixed per server instance; `setupTools` registers the two groups only when a gate is on and the session has a dispatch. The MCP `instructions` gain one sentence per enabled group. The bare single-window `DebugMCPServer` default (tests) has no dispatch and registers neither group.

## Storage

Extracted page text, metadata and indexes live under `<globalStorageUri>/packdocs/` — `<vendor>/<pack>/<version>/<slug>.{pages.jsonl,meta.json,idx.json}` for pack documents, `workspace/<hash>/…`, `user/<hash>/…`, `web|arm/<id>/…` for fetched ones. PDFs themselves stay where they are. The user documents folder defaults to `~/.cmsis-pack-docs/user` so documents imported with the standalone extension stay attributed.
